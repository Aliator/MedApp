# Letters

Letter templates and the PDF engine (PR 15 of `docs/centre-phases-3-5-plan.md`, decisions 98 and 99): read before changing either. Writing, approving and sending letters is PR 16, built on this. **Nothing clinical is generated:** merge fields copy identity and administrative data only; the clinical content is what the author writes (the device position, `docs/clinical-safety/intended-purpose-and-device-decision.md`).

- **A template** (`LetterTemplate`, `MedApp.Domain/Letters`; table `LetterTemplates`, migration `AddedLetterTemplates`): a name (200), a kind (`LetterKind`, stored by number: `ClinicLetter = 0`, `DischargeSummary = 1`, `ReferralResponse = 2`, `InformationRequest = 3`, `AppointmentLetter = 4`, `Other = 5`; never renumber), a specialty (`SpecialtyId`, a restricting foreign key) or null for every specialty, the letterhead (plain lines, 1,000), the body skeleton (Markdown, 20,000, `nvarchar(max)`), the closing (plain lines, 1,000), `IsArchived`, `Version` (a concurrency token) and the times. No patient data: it's an organisation's wording, so reading it records nothing (`EndpointCoverageTests`).
  - **Names are unique within a specialty, ignoring case,** and among those for every specialty: the unique index `IX_LetterTemplates_SpecialtyId_Name` has **no filter** (`HasFilter(null)`; EF would add `IS NOT NULL` for a nullable column), as SQL Server treats nulls as equal. The repository turns its violation into a 409.
  - **Archived, never deleted** (letters will keep a copy of its text, PR 16). A specialty a template is for counts it (`SpecialtyUsage.LetterTemplateCount`), so it can't be deleted, only archived.
  - Text is kept tidied (`LetterTemplateRules.Tidy`: plain line breaks, no blank end). Plain parts keep blank lines (they space the closing for a signature).
- **Merge fields** (`LetterMergeFields`, `MedApp.Application/Letters/Common`): `{{name}}`, case-sensitive, spaces allowed inside the braces. The fixed list: `patient.name`, `patient.dateOfBirth`, `patient.nhsNumber`, `patient.address`, `practice.name`, `practice.address`, `referral.receivedDate`, `appointment.lastAttendedDate`, `author.name`, `author.jobTitle`, `approver.name`, `approver.jobTitle`, `today`, `site.name`. **Never add one that reads a clinical value.**
  - An unknown name in a template is a 400 on the field holding it (`UnknownMessage`), so a typo can't reach a letter.
  - `FillPlain` (letterhead, closing) and `FillMarkdown` (the body: values escaped, so a name with `*` or `[` can't change formatting; a value's lines become hard breaks). A field with no value is left empty and listed in `Missing`: PR 16 refuses approval naming it.
  - `SampleValues` are synthetic (Sam Example, 999 000 0018, ZZ postcodes), with today's real date.
- **The renderer** (`ILetterRenderer`; `PdfSharpLetterRenderer` in `MedApp.Infrastructure/Letters`, a singleton): A4 PDFs from a `LetterDocument` (title, letterhead, recipient address, Markdown body, closing, the patient's identifiers line, large print, an optional marking).
  - **Libraries:** PDFsharp and MigraDoc **6.2.x (MIT)**. **6.5.0 and later are AGPL-3.0:** Dependabot ignores them, and moving needs a licence decision. Markdig (BSD-2-Clause) parses the body, HTML off (`MarkdownToMigraDoc`: headings, paragraphs, bold, italic, nested lists with hanging markers, quotes, rules; code, links (text then address), images (their description) and HTML shown as text). Fully managed: the Dockerfile needs nothing.
  - **The font** is Atkinson Hyperlegible (SIL OFL 1.1), four TTFs embedded in the Infrastructure assembly (`Letters/Fonts`, with `NOTICE.txt` and `OFL.txt`); `LetterFonts` resolves every family to it, as the image has no system fonts. A character it lacks is drawn as `?`; **`FindUnsupportedCharacters` refuses them first** (the template validators do; PR 16 must for patient names and bodies).
  - **Every page** has the patient's identifiers and "Page n of m" in its footer (hazard H-50) and the marking, if any, in its header and footer; large print is 16 point throughout.
  - **Tagged, PDF/A not claimed:** PDFsharp's PDF/A-1a mode (tags, language en-GB, XMP, sRGB output intent). veraPDF passes it while every character is Windows-1252; others (Ł, ş, ğ) fail clause 6.3.5 (PDFsharp writes no CIDSet for the extra font). Tags are one paragraph per page plus the marking; the footer is an artifact. To-do in `docs/todo.md`.
  - **Limited:** at most two renders at a time in each API copy (`PdfSharpLetterRenderer.MaxConcurrent`).
- **Endpoints** (`LetterTemplatesController`, `api/letter-templates`): `GET` (`includeArchived`; every specialty's first, then by specialty name, then name), `GET {id}`, `GET merge-fields`: all `UseApp`. `POST` (201), `PUT {id}` (`expectedVersion`), `POST {id}/archive` and `/restore` (`{expectedVersion}`), `POST preview` (the text, saved or not, and `largePrint`; a PDF of made-up details marked "Preview with made-up details: not a letter" on every page, sent as a download through `AttachmentResponseHeaders`): all `ManageSetup`.
- **The web app:** Letter Templates (`/admin/letter-templates`, `ManageSetup`, in Administration), and its editor (`/admin/letter-templates/new`, `/$id`) with the merge fields listed and Download Preview (PDF).
- **`medapp-dev`:** `reset_demo_data` deletes the templates (`DemoWipe`); the Phase 3 demo data (PR 17) seeds them.
