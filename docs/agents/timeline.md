# Patient timeline

The patient timeline, and what staff and admins may each see in it: read before changing it or the audit details it reads.

The patient page's **timeline** is one feed of what happened to the patient's pathways, appointments and referrals, from the pathway audit log, appointment history (`AppointmentEvent`) and referral history (`ReferralEvent`) (`MedApp.Application/Pathways/Timeline`).
- **Endpoints, for staff:** `GET api/patients/{id}/timeline` (newest first, `Kinds` and `PathwayIds` filters, `Before` cursor) and `GET api/patients/{id}/timeline/overview` (open and blocked pathways, soonest due first, overdue flagged, the pathways to filter by, and referrals awaiting triage, `awaitingReferrals`: specialty, date received, priority asked for). Both 404 for an unknown patient.
- **Kinds** (`PatientTimelineKind`): Created, Stages, Notes (stage and pathway notes), Assignments, Blocks (cancelling a blocked pathway is Status), Status, DueDates, Details, Deleted, Files (attached or deleted, never downloads) and Appointments (every history entry: requested, booked, rescheduled, attended, did not attend, cancelled, notes changed, recorded after the event and entered in error) and Referrals (every referral history entry, as `Referral<Action>`: `ReferralRegistered`, `ReferralDetailsEdited`, `ReferralWithdrawn`, `ReferralEnteredInError`, and triage's `ReferralAccepted`, `ReferralRejected`, `ReferralRedirectedElsewhere`, `ReferralSpecialtyChanged`). A pathway's Created entry from a referral carries its `ReferralId`. Specimens is a kind too (audit actions 16 to 23: taken, sent, received, reported, rejected, lost, entered in error, details edited: [Specimens](specimens.md)). `PatientTimelineKinds` computes them alike in memory and SQL, from markers in the JSON details. Not stored, so they can be regrouped; a change to `PathwayAudit`'s details must keep its tests passing.
- **Three feeds, merged** by time with the same filters, so one cursor pages through all three (`ReferralTimelineSearch` for referrals). An appointment entry's `PathwayId` and `PathwayTitle` are null when it isn't for a pathway; a referral entry has `ReferralId` and `SpecialtyName`.
- **What each person sees is decided on the server** (`GetPatientTimelineQuery.FullView`, for holders of `ViewAudit`), because the audit log is admin-only and keeps old values:
  - **Staff** see entries only for existing pathways: kind, who (the username then, a deleted account's too), when, the pathway (a link) and structured old and new values (target dates, priorities, statuses, template, assignees). For appointments: status, time, member of staff, stage; nothing for a deleted pathway's. **Never free text:** no note text, titles, block or cancel reasons, file names, appointment notes, or the reason for finishing without a visit; only which field changed (a pathway note's is `note`, with no values). For referrals: the action, who, when, the specialty, the priority asked for, the status, and the names of edited fields with values only for the specialty, date received and priority (`TimelineMapper`'s `ReferralValueFields`); for triage, the template and priority chosen and the pathway (`ReferralAccepted`), the rejection reason by name (`RejectionReason`), and the specialty it was redirected from (`PreviousSpecialtyName`); never the reason, the referrer, the detail or where it was redirected. For specimens: the number, type, lab, statuses and an edit's structured values (type, lab, taken time, requesting clinician); never the site, request notes, rejection reason or any detail.
  - A file on the patient themselves has pathway ID `PatientPathwayAuditEntry.NoPathway` (all zeros) and an empty title.
  - **Admins** see everything: deleted pathways' entries (labelled, with the title then), file names, appointment notes and reasons, finishing-without-visit reasons, deletion reasons and details, and note text from the versions (before an edit, and a deleted note's) (`GetPatientTimelineHandler`, `PatientTimelineRow.NoteText`). For referrals, also the reason (on Registered), the detail (on Withdrawn, EnteredInError, Rejected and RedirectedElsewhere; the redirect detail on SpecialtyChanged, the latest only), where it was redirected (`RedirectedTo`) and the referring practice, read from the referral row (`ReferralTimelineRow`): the history keeps no old text, so an edit's free-text fields come by name only. For specimens, also the site and request notes (on Taken) and the closing detail and rejection reason, read from the specimen (`PatientTimelineRow.Specimen`, loaded only for the full view).
  - **Adding a field to `PatientTimelineEntryResponse`:** audit free text goes to admins only (`TimelineMapper`'s `PublicValueFields` allowlists edited fields). `TimelineStaffCanaryTests` records every action with one string as all free text and checks no staff response holds it; add any new action or free-text field there (every referral action written so far is in it).
  - `docs/governance/` states this rule; change both together.
- An entry shows the pathway's current title, or once deleted the title recorded then (so a rename before deletion shows under both).
- **Order:** `AtUtc` then `Id`, newest first. One change's entries are each a tick (100 ns) apart (`PathwayChange.Audit`), so they sort in order; older entries sharing a time fall back to ID.
