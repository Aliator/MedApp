# Review: PR #169, pathways that branch

**PR:** [#169](https://github.com/Aliator/MedApp/pull/169), branch `feature/branching-pathways`, reviewed at `f0ff07b` on 18 November 2026. A safety review of optional stages, branch points, skipping and reinstating, the migration `AddedStageBranches` and the template editor. No finding is high or critical.

Adds optional stages and branch points to templates (`TemplateBranchRules`), skipping an optional stage (`POST …/stages/{sid}/skip`, `WorkPathways`), choosing a branch when a branch point is finished (`branch` on finish; the other branches' stages to do are skipped as `BranchNotChosen`), and reinstating a skipped stage (`POST …/stages/{sid}/reinstate`, `OverrideStages`). Audit actions `StageSkipped = 35`, `BranchChosen = 36`, `StageReinstated = 37`; `StageSkipReason`. The current stage is the first neither finished nor skipped (`PathwayWorkflow.IsToDo`).

**Findings:**
- **Medium, fixed:** an admin could mark a Required-visit stage optional (`TemplateBranchRules.WhyInvalid` doesn't look at `VisitRequirement`), and any holder of `WorkPathways` could then skip it as "Not needed" (`PathwayWorkflow.WhySkipNotAllowed`), cancelling its visit, though finishing it without the visit needs `OverrideStages` and a reason. Fixed: `WhySkipNotAllowed(pathway, stage, canOverrideStages)` refuses a Required-visit stage without `OverrideStages` (409), `SkipPathwayStageHandler` needs a detail for one (400, `DetailRequiredMessage`), the `StageSkipped` entry records `visitRequirement`, and the stage's `canSkip` follows the viewer's `OverrideStages` (`PathwayMapper`). A branch not chosen still skips such a stage, as designed. Tests: `SkipPathwayStageHandlerTests` (three cases), `PathwayWorkflowBranchTests.CanSkipStage_RequiredVisit_NeedsOverrideStages`; added to H-51's controls.
- **Low, fixed:** the finish dialog's "These stages will be skipped" listed every stage of the other branches (`StageSkipDialogs.tsx`, `stagesSkippedBy`), but the server skips only those still to do (`StagesSkippedByBranch`, `IsToDo`). Fixed: each branch in the response gains `stageNamesToDo`, which the dialog lists.
- **Low, fixed:** a template edit without `stageOptions` made every stage plain, so a page loaded before this release would strip a template's branches on save. Fixed: `UpdatePathwayTemplateHandler.KeptOptions` keeps the stored options when the stage list is unchanged (same definitions in the same order); a new list without options is still plain.

**Also with these fixes:** `main`'s waiting-time clock (#166) merged in. A skipped clock-stop stage stops nothing (the clock stops at discharge or cancellation), and reinstating never restarts a stopped clock (`PathwayChangeClockTests`, `WaitingClockTests.SkippedClockStopStage_StopsNothingUntilDischarge_AndReinstatingNeverRestartsIt`). The migration was rebuilt on `AddedWaitingTimeClock`.

**Remaining risk:** during a rollout an API copy from before this release shows a skipped stage as current and would let staff finish it (`docs/todo.md`); demo data has no branches until PR 28, so the new UI parity screens skip until then.
