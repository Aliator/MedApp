# Results

Results sign-off: read before changing results, their list, or the results stage gates.

Concept and decisions: `docs/centre-phases-3-5-plan.md`, section 2.3 (decisions 91 to 97) and PR 14. A **result** (`Result`, `MedApp.Domain/Results`; table `Results`, migration `AddedResults`) is a report a named clinician must sign off. **MedApp never reads, interprets or flags a result's contents**: the report is an attached file, shown as it came (a thumbnail or a download); a clinician marks it seen and records what they did, in their own words; nothing is suggested (`docs/clinical-safety/intended-purpose-and-device-decision.md`).
- **Where results come from:** a specimen's report (`ReportSpecimenHandler` makes one in the same save as the report: `ISpecimenRepository.SaveReportAsync(report, result, audit)`; its title is the type and number, its responsible clinician the requesting clinician), or an attached file marked as an external result (`POST api/results/external` `{attachmentId, title, pathwayId?, responsibleUserId}`, `WorkPathways`, 201): the file must be live, on the patient, a pathway or a stage (not a referral's letter: 400), not already a result's report (409); its pathway is the file's own (another is a 400) or, for a file on the patient, the one given or none. A restricted record's can't be recorded (409: new work); an anonymised one's neither.
- **Stored enums, never renumbered:** `ResultStatus` (`AwaitingSignOff = 0`, `Seen = 1`, `SignedOff = 2`, `EnteredInError = 3`), `ResultSource` (`Specimen = 0`, `ExternalReport = 1`), `ResultAction` (`NoFurtherAction = 0`, `PatientInformed = 1`, `AppointmentArranged = 2`, `ForMdtDiscussion = 3`, `ReferredOn = 4`, `Other = 5`). Audit actions `ResultRecorded = 24` to `ResultEnteredInError = 28`; `ActivityAction.ResultViewed = 46`; `NotificationKind` `ResultReady = 26`, `ResultReassigned = 27`, `ResultSignedOffByOther = 28`.
- **Where the rules live** (`MedApp.Application/Results/Common`): `ResultWorkflow` (what each status allows, who may mark one entered in error, the gate's message, age in days), `ResultChange` (**the only way to change a result**: bumps `Version`, writes its audit entries), `ResultMapper`, `ResultNotifications`, `ResultRules`. `IResultRepository` shares the request's DbContext, so entered in error saves the result, its specimen and its file's deletion together.
- **Permission** `SignOffResults` (group Results; Clinician and Senior clinician; **not Admin's**: clinical, `Permissions.NotForAdmin`): mark seen, sign off, take over, reassign, and be a responsible clinician (a specimen's requesting clinician must hold it: `SpecimenChoices.RequestingClinicianPermission`).
- **Sign-off** (decision 93): `POST api/results/{id}/seen` `{expectedVersion}` (optional, once), `POST …/sign-off` `{action, detail?, expectedVersion}` (detail 1,000, required for Other; final: a later change goes in a pathway note). Any holder may sign off; if not the responsible clinician, they're told (`ResultSignedOffByOther`). The actions are listed in a fixed order with none pre-selected; MedApp never checks one fits.
- **Responsible clinician** (decision 92): `POST …/reassign` `{responsibleUserId, expectedVersion}`, to a holder of `SignOffResults` (400 otherwise, or for the same one); the caller's own ID takes it over. The new one is told (`ResultReassigned`) unless they took it. A result whose responsible clinician no longer holds the permission (or whose account has gone) shows **Needs a clinician** (computed from `IPermissionHolders`, not stored).
- **Entered in error** (decision 96, hazard H-47): `POST …/entered-in-error` `{detail, expectedVersion}` (500), endpoint `ViewPatients`, the handler checking who (403): a holder of `CorrectRecords` at any time, or whoever reported it within 24 hours while they still hold `ProcessSpecimens` (a specimen's) or `WorkPathways` (an external one). Allowed in any status but entered in error (a signed-off report on the wrong patient must still be correctable). It closes the result, soft-deletes the report file (an `AttachmentDeleted` entry), and puts a specimen back to Received with its report cleared and its version moved on (recorded in the `ResultEnteredInError` entry's `specimenStatus`), so the lab attaches the right report and a new result is made (the unique index `IX_Results_SpecimenId` ignores entered-in-error results).
- **Restricted records** (decision 75): seen, sign-off, reassign and entered in error are allowed (a result must never be stuck); anonymised: nothing changes (409).
- **The gates** (decision 95, `StageGates.WhyResultsAwaiting`, `FinishPathwayStageHandler`): a stage whose definition has `WaitsForResults` (copied onto each pathway's stage; on the definition, as `NeedsLetterKind` is, not the template map) and always the pathway's last stage can't be finished while any of the pathway's results awaits sign-off (409, naming their report dates only). No override.
- **Lists** (`GET api/results/search`, `ViewPatients`; `ResultSearch`, LINQ that runs in SQL and in memory): `AwaitingMine`, `Awaiting`, `NeedsClinician` (oldest report first), `SignedOff` (newest signed off first), `All` (the default, newest report first), with `teamId` (the pathway's), `pathwayId` and `patientId`, `search` (the patient's name only: a title can hold a specimen number, which stays out of URLs) and `sort` (`patient`, `title`, `pathway`, `reported`, `status` then signed off) with `ascending`, a column only when the person asks; records `PatientListed`. `GET api/results/count` (`{awaitingMine}`, the side nav) records nothing. Ordered by dates only.
- **Files:** a result's report can't be deleted on its own (`DeleteAttachmentHandler`: 409, admins too; decision 71). A pathway or patient with results can't be deleted (409; the foreign keys too).
- **Privacy** ([privacy](privacy.md)): `GET api/results/{id}` records `ResultViewed` (`{resultId}`). The audit holds the result's ID, source, the specimen's ID, number and type, statuses, the action by name, the file's ID and usernames; **never** the title, action detail or error detail. Staff's timeline (kind `Results`) shows those; admins also the title (on Recorded), the action's detail and the error detail, read from the result (`PatientTimelineRow.Result`). Notifications have fixed titles and say only who (and the specimen type). Export: every result with its free text (`ExportedResultResponse`). Anonymisation is refused while one awaits sign-off, then replaces the title, action detail and error detail.
- **The web app:** Results (`/results`, side nav with the count of mine awaiting), a result's page (`/results/$id`), the pathway page's Results card, Record as result on a file, Waits for results on the stage library.
- **`medapp-dev`:** `reset_demo_data` deletes results (`DemoWipe`); demo results come with Phase 3's demo data (PR 17).
